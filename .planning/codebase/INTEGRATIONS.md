# External Integrations

**Analysis Date:** 2026-08-27

## APIs & External Services

**Model providers:**
- The frozen provider catalog is the sole endpoint, wire, route, and credential-name authority (`crates/nano-model/data/providerCatalog.vendored.json`, generated by `crates/nano-model/build.rs`). Runtime configuration may select catalog IDs but may not add or redirect endpoints.
- Flux Router - primary OpenAI-compatible chat-completions route and Anthropic-compatible route at `api.fluxrouter.ai`; model listing, responses, grounding, and live MCP code also exist in `crates/nano-model/src/` and `crates/nano-mcp/src/http.rs`.
  - SDK/Client: internal `nano-model` clients over `nano-egress`/Reqwest.
  - Auth: `FLUX_API_KEY`, `FLUX_TEST_KEY`, or file path in `FLUX_API_KEY_FILE`; injected OAuth bearer variables are generated from the provider ID.
- Proven catalog providers - OpenAI, Anthropic, Google Gemini, OpenRouter, Groq, Mistral, DeepSeek, Together, Fireworks, Perplexity, Cohere, Cerebras, xAI, and Moonshot (`crates/nano-model/data/providerCatalog.vendored.json`).
  - SDK/Client: provider-neutral OpenAI-completions or Anthropic-messages wire implementations in `crates/nano-model/src/`.
  - Auth: the catalog's canonical `*_API_KEY`, the corresponding `*_API_KEY_FILE`, or short-lived `WAYLAND_NANO_OAUTH_BEARER_<PROVIDER>` plus expiry metadata (`crates/nano-cli/src/provider_key.rs`).
- Cataloged but fail-closed/unproven providers - NVIDIA and MiniMax remain present but unroutable until live proof flips their explicit `proven` flags (`crates/nano-model/src/provider_catalog.rs`).

**Search and web:**
- Flux grounding/search - preferred search path when Flux credentials and a session meter are available (`crates/nano-cli/src/search_specs.rs`, `crates/nano-model/src/flux_grounding.rs`).
- Brave Search - optional exact-host backend at `api.search.brave.com`, authenticated by `BRAVE_SEARCH_API_KEY` (`crates/nano-cli/src/search_specs.rs`).
- Tavily Search - optional exact-host backend at `api.tavily.com`, authenticated by `TAVILY_API_KEY` (`crates/nano-cli/src/search_specs.rs`).
- Generic web fetch - HTTPS exact-host allowlist from `NANO_WEB_FETCH_HOSTS`; plain HTTP requires explicit per-host opt-in (`crates/nano-cli/src/fetch_specs.rs`).

**Model Context Protocol:**
- MCP 2025-06-18 client supports contained stdio servers and streamable HTTP/JSON-RPC servers (`crates/nano-mcp/src/protocol.rs`, `crates/nano-mcp/src/stdio.rs`, `crates/nano-mcp/src/http.rs`).
  - Configuration: ACP `mcpServers` plus operator `NANO_MCP_SERVERS`, isolated per session (`crates/nano-cli/src/acp_mode.rs`).
  - Security: HTTP flows through `nano-egress`; stdio processes use contained spawn and bounded teardown; no MCP path bypasses sandbox/egress policy (`crates/nano-mcp/src/lib.rs`).
  - OAuth: Authorization Server discovery, PKCE S256, bounded exact-endpoint egress grants, optional dynamic client registration, credential storage, login/status/logout (`crates/nano-mcp/src/oauth/`, `crates/nano-cli/src/auth_cmds.rs`).

**Plugin registries:**
- Local registries and GitHub repositories provide plugin marketplace metadata and tarballs (`crates/nano-plugins/src/source.rs`, `crates/nano-plugins/src/fetch.rs`).
  - SDK/Client: internal fetcher over `nano-egress`/Reqwest with SHA-256 and tar/gzip verification.
  - Network allowlist: `github.com` and `codeload.github.com` only for GitHub sources.
  - Limitation: HTTP MCP plugins are rejected in v1 (`crates/nano-plugins/src/error.rs`).

**Desktop protocols:**
- Wayland Desktop integrates through the ready-first proprietary NDJSON protocol host and ACP v1 host (`crates/nano-cli/src/host_mode.rs`, `crates/nano-cli/src/acp_mode.rs`, `crates/nano-protocol/`).
- ACP session creation supplies models, connectors/MCP servers, prompt blocks, streamed updates, and session lifecycle; local host processes communicate over stdio rather than a hosted service.

## Data Storage

**Databases:**
- Embedded SQLite, compiled from bundled source through Rusqlite, stores P-MEM core memory (`crates/nano-memory/Cargo.toml`).
  - Connection: local database path passed to `MemoryStore`; there is no remote connection string or database service (`crates/nano-memory/src/store.rs`).
  - Client: Rusqlite 0.37.
  - Indexes: SQLite FTS5 BM25 plus sqlite-vec KNN; embeddings are deterministic local 384-dimensional hashes with no network call (`crates/nano-memory/src/schema.rs`, `crates/nano-memory/src/embed.rs`).
  - Partitioning: every memory row is keyed by project and `agent_id`; bi-temporal fact/decision/episode/procedure tables, retention controls, and unpopulated KG schema ship together (`crates/nano-memory/src/schema.rs`).

**File Storage:**
- Append-only JSONL operation journals and attachment blobs are local and controlled by `nano-session` (`crates/nano-session/`). Journals are the durability/rebuild source for memory writes (`crates/nano-memory/src/store.rs`, `crates/nano-memory/tests/durability.rs`).
- Checkpoints, goals, tasks, cron jobs, receipts, plugin state, rules, and OAuth fallback records use namespaced local files under the configured Nano home or repository (`crates/nano-checkpoints/`, `crates/nano-agent/src/`, `crates/nano-verify/`, `crates/nano-plugins/`).
- No cloud file or object store is integrated.

**Caching:**
- No external cache service. Provider catalog code generation, local plugin downloads, session state, model routing snapshots, and repository maps use process-local or filesystem state.

## Authentication & Identity

**Auth Provider:**
- Model/API authentication is provider-specific but resolved through one catalog-governed path (`crates/nano-cli/src/provider_key.rs`).
  - Implementation: injected short-lived bearer token first, canonical catalog API-key environment variable second, then owner-only key file named by `<VAR>_FILE`; Flux retains its explicit three-source precedence in `crates/nano-cli/src/flux_key.rs`.
- MCP OAuth uses OAuth 2 authorization-code flow with PKCE S256 (`crates/nano-mcp/src/oauth/`).
  - Implementation: explicit user approval for discovered authorization-server origin, exact egress grants for discovery/token endpoints, OS credential store primary on Windows, and explicitly named refresh-token file fallback where configured (`crates/nano-cli/src/auth_cmds.rs`, `crates/nano-mcp/src/oauth/storage.rs`).
- There is no application user-account service or remote Wayland Nano identity provider in the current runtime.

## Monitoring & Observability

**Error Tracking:**
- No hosted error-tracking service is integrated.

**Logs:**
- Rust `tracing` and structured/typed protocol error events are used locally; security-sensitive errors are redaction-safe (`crates/nano-egress/src/redact.rs`, `crates/nano-session/src/`).
- Append-only journals, verifier receipts, gate artifacts, proof manifests, soak logs, and CI artifacts provide auditable evidence (`crates/nano-session/`, `crates/nano-verify/`, `gates/`, `scripts/`).
- Optional metrics use the `nano.*` namespace and local proof/evidence files; no telemetry exporter or remote metrics backend is detected (`docs/metrics/`).

## CI/CD & Deployment

**Hosting:**
- Native binaries are distributed as public npm package `waylandnano` and GitHub Release archives (`packaging/npm/package.json`, `.github/workflows/release.yml`).
- The repository and release artifacts are hosted on GitHub; no runtime server deployment is required.

**CI Pipeline:**
- GitHub Actions gate workflow validates formatting, Clippy, tests, dependency policy, generated contracts, SBOMs, packaging, and platform-specific security behavior (`.github/workflows/gate.yml`).
- The primary matrix covers Windows, Ubuntu, and macOS across x64/arm64 check/build legs, including the Windows ARM64-sensitive native SQLite/sqlite-vec stack (`.github/workflows/gate.yml`).
- Tagged release workflow builds five binary platforms, stages Unix PTY guards, signs Windows executables through Azure Trusted Signing when configured, verifies signatures, publishes npm with provenance, creates GitHub release archives, and attaches SLSA build provenance (`.github/workflows/release.yml`).

## Environment Configuration

**Required env vars:**
- No credential is required for local offline build/test; live-gated tests self-skip without keys (`README.md`, `AGENTS.md`).
- Model use requires one credential source for the selected provider: catalog `*_API_KEY`/`*_API_KEY_FILE`, injected `WAYLAND_NANO_OAUTH_BEARER_*`, or Flux-specific `FLUX_API_KEY`, `FLUX_TEST_KEY`, `FLUX_API_KEY_FILE` (`crates/nano-cli/src/provider_key.rs`, `flux_key.rs`).
- Optional integrations: `NANO_MCP_SERVERS`, `NANO_WEB_FETCH_HOSTS`, `NANO_SEARCH_BACKEND`, `BRAVE_SEARCH_API_KEY`, `TAVILY_API_KEY`, and MCP refresh-file variables (`crates/nano-cli/src/`).
- Runtime/policy settings use namespaced variables such as `NANO_HOME`, `NANO_RULES_FILE`, `NANO_DEFAULT_MODEL`, `NANO_REASONING_EFFORT`, and `WAYLAND_NANO_PROVIDERS` (`crates/nano-cli/src/`).
- Release-only GitHub configuration uses repository secrets/variables for npm publishing and optional Azure signing, referenced symbolically in `.github/workflows/release.yml`.

**Secrets location:**
- Secrets must remain outside the repository. The repository rule permits only path references to the external `.secrets` location and expressly forbids reading, printing, or committing its contents (`AGENTS.md`).
- OAuth refresh credentials use the OS credential manager when supported or an explicitly configured owner-only fallback file (`crates/nano-mcp/src/oauth/storage.rs`).

## Webhooks & Callbacks

**Incoming:**
- MCP OAuth temporarily binds a local loopback callback listener for authorization-code completion (`crates/nano-mcp/src/oauth/loopback.rs`).
- MCP streamable HTTP receives server responses/notifications over an outbound client connection; Wayland Nano does not expose a general public HTTP server (`crates/nano-mcp/src/http.rs`).
- ACP and Desktop-core requests arrive through local stdio NDJSON hosts, not webhooks (`crates/nano-protocol/`, `crates/nano-cli/src/acp_mode.rs`).

**Outgoing:**
- Model, search, web fetch, MCP HTTP, OAuth, and plugin registry requests all pass through the `nano-egress` chokepoint and an explicit host or exact-endpoint policy (`crates/nano-egress/src/client.rs`, `crates/nano-egress/src/policy.rs`).
- GitHub Actions publishes to npm, GitHub Releases, Azure Trusted Signing, and the RFC 3161 timestamp endpoint only in release workflow context (`.github/workflows/release.yml`).
