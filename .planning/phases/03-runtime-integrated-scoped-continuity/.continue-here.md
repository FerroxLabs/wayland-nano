## Blocking contract contradiction

Plan 03-02 requires every persistent entrypoint (ACP session/new and load, protocol-host, and exec) to resolve and journal one host MemoryPolicy while restricting writes to `memory_policy.rs`, `activation.rs`, and `acp_mode.rs` on the CLI side. The live code has no allowed shared journal locus:

- ACP opens session coordinators in `crates/nano-cli/src/acp_mode.rs` (allowed).
- Exec opens its coordinator in `crates/nano-cli/src/exec_run.rs:170` (not plan-owned).
- Protocol-host opens its coordinator in `crates/nano-cli/src/host_mode.rs:171` (not plan-owned).
- `crates/nano-cli/src/activation.rs` authenticates/mints carriers but owns no session journal.

Two additional incompatibilities prevent an exact implementation:

1. Existing `nano_session::Op::MemoryPolicyResolved` (`crates/nano-session/src/op.rs:1772`) carries policy fields and optional `session_id`, but no `project` or `agent_id`, although 03-02 requires all three and does not authorize `op.rs` edits.
2. `nano-memory::store::validate_policy` is private (`crates/nano-memory/src/store.rs:1020`), and `nano-cli` has no `nano-memory` dependency. The plan forbids package changes and does not authorize `Cargo.toml` or a public nano-memory API change.

Implementing only ACP would violate the every-entrypoint requirement. Editing `exec_run.rs`, `host_mode.rs`, `op.rs`, Cargo manifests, or nano-memory would violate file ownership/scope and the explicit no-nano-memory rule. No workaround was attempted.
