<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| Desktop key derivation → Nano dedup | A nondeterministic or collision-prone key turns retries into duplicate executions or cross-routine theft. |
| Retried trigger → effect dispatch | Receipt replay must short-circuit before any effect; otherwise a duplicate trigger double-fires side effects. |
| Retry-conflict semantics → operator safety | Weakening the conflict error to accommodate deterministic keys can silently accept changed-payload reuse. |
| Desktop edit scope → repo governance | Edits outside the authorized worktree/owned paths bypass the Phase 2 governance pattern. |
